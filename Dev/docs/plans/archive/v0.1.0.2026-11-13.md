## 1. Context, Goal, Problem Statement & Report Reconciliation Matrix

### 1.1 Objective & Architectural Background
`reEngine` is the ecosystem's **zero-daemon top-level `.recomp` suite router and side-by-side platform engine manager** (`0 MB` background RAM, `AllowAutoStart = false`, `<PROGRAMS_ROOT>\reEngine\`). Unlike `Mother` (`:5100`), `reEngine` never runs a background tray daemon or Windows Startup entry. Instead:
1. Any `re*` engine (`reStation`, `re64`, `reCube`) or `<Game>Recomp` installer invokes `ReEngineBootstrapHelper` (shipped in `<PROJECTS_ROOT>\SharedLibs\reEngine\v<Ver>\`) to deploy or idempotently upgrade `reEngine` and install platform engines side-by-side under `engines\re<Platform>\v<Ver>\`.
2. Double-clicking a `.recomp` file (or invoking `reEngine.exe --open <path>`) parses the Standard 18 `camelCase` manifest, discovers gitignored user optical/ROM media in `data\rom\` (`preloadRomDir`), resolves the highest compatible installed engine track (`compatibleEngineTrack` + `>= engineVersion`) while ignoring newer breaking tracks, optionally runs a non-blocking update check (`shouldCheckUpdates` / `shouldAutoStagePatches`), and launches the target engine cleanly via `JobObjectGuard`.
3. Launching `reEngine.exe` without `--open` opens a compact Dark Slate WinForms Suite Manager (`#0E0E10` / `#18181B` / `#38BDF8`) displaying installed side-by-side engines, `.recomp` shell registration status, `data\rom\` preload discovery, and update controls.

### 1.2 Impact & Severity
- **Classification:** `Feature` (Greenfield `v0.1.0` Baseline Implementation)
- **Blast Radius:** High ecosystem leverage — `reEngine.Core` (`ReEngineBootstrapHelper`) becomes the immutable shared contract in `<PROJECTS_ROOT>\SharedLibs\reEngine\v0.1.0\` consumed by `reStation` and `<Game>Recomp` installers.
