## 5. Architecture & Technical Design

### 5.1 Launcher Sync-Wait, Relative-Path Normalization & Exit Code Contract (`T1`)
Because [`RootLauncherHost.Run`](<PROJECTS_ROOT>/Personal/Foundation/Dev/src/Foundation.Launcher/RootLauncherHost.cs#L51-L141) changes `WorkingDirectory` to `app\` without normalizing relative CLI paths and omits `--open`, `--wait`, `--check-updates`, `--register-assoc`, `--visible-test`, and `--test-mode` from `ShouldWaitForChild`, `reEngine.Launcher` implements a compact (`<= 140 LOC`) local launcher helper while still calling `RootLauncherHost.ResolveTargetExecutable` so `Foundation.Launcher` continues being consumed:
- **`ShouldWaitForChild(string[] args)`:** Returns `true` when `args` contains any sync flag (`--open`, `--wait`, `--check-updates`, `--register-assoc`, `--visible-test`, `--test-mode`, `--headless`, `--dry-run`, `--help`, `-h`, `/?`, `help`, `--version`, `-v`) **or** a leading non-flag positional `.recomp` path (skipping option values via the complete `ValueOptions` set matching [`Program.cs#L19-L22`](<REPO_ROOT>/Dev/src/reEngine.App/Program.cs#L19-L22) + `T3` passthrough flags: `--open`, `--engines-dir`, `--data-dir`, `--config`, `--log-dir`, `--feed`, `--port`, `--ui`, `--frames`, `--fixture`, `--dump-screenshot`, `--dump-audio`, `--input-script`, so `--port 15100` or `--ui desktop` is never misclassified as a positional path). Only a bare `reEngine.exe` invocation (`args.Length == 0`) or explicit GUI launch without sync flags detaches asynchronously and exits `0`.
- **`NormalizePathArguments(string[] args, string callerWorkingDirectory)`:** Before spawning `app\reEngine.exe` with `WorkingDirectory = app\`, resolves relative filesystem paths to `Path.GetFullPath(rawValue, callerWorkingDirectory)` for:
  - Both `--opt value` and `--opt=value` forms of `--open`, `--engines-dir`, `--data-dir`, `--config`, `--log-dir`, `--feed` *(ONLY when not an `http://` or `https://` URI!)*, `--fixture`, `--dump-screenshot`, `--dump-audio`, `--input-script` (leaving non-path `--port` and `--ui` values verbatim);
  - Non-flag positional arguments (skipping values paired with the full `ValueOptions` set above).
- **Exit Code Propagation (`0, 1, 2, 3, 4, 5, 6, 130`):**
  - `Console.CancelKeyPress` sets `cancelEventArgs.Cancel = true` while waiting and attempts clean teardown returning **`130`** if aborted via Ctrl+C.
  - Otherwise returns `proc.ExitCode` **verbatim** (`0..6`, `130`, etc.).
- **CLI Exit Code Semantics in `reEngine.App`:**
  - `0`: Success (or offline/unavailable `--check-updates` graceful `[WARN]` without `--strict`).
  - `1`: General runtime failure, missing resolved engine, unrelated `InvalidOperationException`, or child failure.
  - `2`: Fail-closed Sandbox containment breach (`SandboxEnvironment.AssertPathContained` `"Fail-Closed Sandbox Violation..."` or [`RecompPackageReader`](<REPO_ROOT>/Dev/src/reEngine.Core/Manifests/RecompPackageManifest.cs#L151,L193,L208,L229,L236,L243) `"Fail-Closed Containment Violation..."` `InvalidOperationException`), Zip-Slip / malformed `.recomp` `InvalidDataException` or `JsonException` during package parsing, or invalid/missing CLI option `ArgumentException`.
  - `4`: Update/feed network check failure when `--check-updates --strict` is set (`StrictUpdateCheckFailed`).
  - `130`: User/signal cancellation (`OperationCanceledException` when cancellation requested).

### 5.2 Offline Update Resilience & Multi-Engine `(EngineId, Track)` Sweep (`T2`)
Extraction into `reEngine.Core\Updates\UpdateCoordinator.cs` eliminates CLI vs. WinForms UI duplication:
- **New Models & Method on `UpdateCoordinator`:**
  ```csharp
  public sealed record UpdateCheckOutcome(
      bool Checked,
      bool CompatiblePatchAvailable,
      bool CompatiblePatchStaged,
      string? StagedPatchPath,
      bool BreakingUpdateAvailable,
      string? BreakingVersion,
      string StatusMessage,
      bool NetworkUnavailable = false);

  public sealed record MultiEngineUpdateSweepResult(
      bool SweepExecuted,
      bool NetworkUnavailable,
      IReadOnlyList<UpdateCheckOutcome> Outcomes,
      string SummaryMessage);
  ```
  *(Note: `MultiEngineUpdateSweepResult` uses Standard 18-clean **`SweepExecuted`** (`check_schema_registry.ps1` `STATUS: CLEAN`; `"checked"` is a banned synonym of `isVerified`); `UpdateCheckOutcome.Checked` is kept solely for in-memory `v0.1.0` compatibility and is never JSON-serialized.)*
- **`CheckAllInstalledEnginesAsync(...)` Flow:**
  1. Inspects `installedEngines`. Groups candidates by `(EngineId (OrdinalIgnoreCase), Track = $"{Version.Major}.{Version.Minor}.x")` selecting the highest installed `SemVer` per distinct track; falls back to single default target `("reStation", new SemVer(0, 1, 0), "0.1.x")` if `installedEngines.Count == 0`.
  2. Resolves `feedSource`; if updates disabled or no feed URL configured, returns skipped summary cleanly without network I/O.
  3. Calls `FetchFeedManifestAsync` **once** inside a tight network-fault `try/catch` filtering strictly for transport/feed failures (`HttpRequestException`, `SocketException`, `IOException` during HTTP/stream fetch, `TimeoutException`, or `TaskCanceledException` when `!ct.IsCancellationRequested`, plus HTTP/JSON parse failures via `JsonException`). **Never** catches `InvalidOperationException` from `SandboxEnvironment.AssertPathContained` or `ArgumentException` — containment breaches still abort fail-closed!
  4. On network fault: returns `MultiEngineUpdateSweepResult(SweepExecuted: false, NetworkUnavailable: true, Array.Empty<UpdateCheckOutcome>(), $"Update check skipped (offline/unavailable): {ex.Message}")` and logs `[WARN]` cleanly (**`0` crash dumps written**).
  5. Evaluates `EvaluateAndStageAsync` for every `(EngineId, Track)` target (catching transient download faults per patch identically if a patch download drops mid-stream, surfacing `NetworkUnavailable = true` rather than an unhandled crash).
