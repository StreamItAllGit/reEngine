## 1. Executive Summary of Defect
Read-only log forensics and isolated probes against `reEngine v0.1.0` confirmed **five runtime/contract defects** blocking lockstep `0.1.x` integration with `reStation` and `KingsFieldRecomp`:
1. **`P1` — Unhandled `--check-updates` Socket Drop Crash + Empty `"recentLogs": []`:** Offline/refused/reset feed sockets threw an unhandled `HttpRequestException` (`SocketException 10054` / `10061`) out of `RunUpdateCheckCliAsync` to `Program.Main`, crashing with exit code `1` and writing a crash bundle whose `"recentLogs"` array was unconditionally `[]`.
2. **`P1` — Root `reEngine.exe` Async Detach & Missing `--wait` / `--open` Sync Propagation:** Delegating to `Foundation.Launcher.RootLauncherHost.ShouldWaitForChild` caused root `reEngine.exe` to return `0` in `~88–94 ms` without waiting whenever `--open`, `--wait`, `--check-updates`, or `--register-assoc` was used without `--dry-run` or a positional non-flag `args[0]`, silently masking child crashes (`exit 1`).
3. **`P1` — `RecompLaunchCoordinator` CLI Contract Collision (`--preload-media`) & Unforwarded Flags:** `RecompLaunchCoordinator.SpawnEngineAsync` emitted `--preload-media <path>` (rejected with exit code `2` by `reStation v0.1.0` `CliOptions.Parse`, which only recognized `--disc`), did not accept or forward `--wait` / `--log-dir` / `--config`, and shared `DataDirectory` with the launched child engine.
4. **`P2` — Duplicate `[HEARTBEAT]` Prefix in `reengine.log`:** `HeartbeatLogger` prepended `[HEARTBEAT]`, and `Program.cs` passed `line => log("HEARTBEAT", line)`, producing `[HEARTBEAT] [HEARTBEAT]` lines.
5. **`P3` — Single-Engine Update Selection (`FirstOrDefault()`):** `RunUpdateCheckCliAsync` inspected only the first engine returned by `DiscoverInstalledEngines` (sorted descending by version), skipping `0.1.x` patch checks whenever `0.2.0+` was installed side-by-side.

## 4. Root Cause Analysis

1. **Uncaught Offline Network Exceptions & Empty `recentLogs`:**
   - `RecompLaunchCoordinator.TryNonBlockingUpdateCheckAsync` wraps `CheckAndStageAsync` in a `try/catch` that logs `[WARN]`, whereas `Program.RunUpdateCheckCliAsync` awaited `coordinator.CheckAndStageAsync(...)` bare. Any `HttpRequestException` / `SocketException` / `TaskCanceledException` unwound into `Program.Main`'s `catch (Exception ex)`.
   - Inside that `catch` block, `Program.cs` invoked `CrashBundleService.TryWriteCrashBundle` without passing the `logLines` queue snapshot (unlike `RegisterGlobalHandlers`).
   - Additionally, `reengine.log` emitted `timestamp [LEVEL] msg` rather than Standard 15 §5.1 `[v0.1.0] [PID:<pid>/T:<tid>] [component]`, and upstream `Foundation.Core.CrashBundleService` wrote `crash_reengine_YYYYMMDD_HHMMSS_fff.json` without `_v<BuildVersion>` or a 20-bundle pruning cap.

2. **Root Launcher Sync-Wait Bypass (`reEngine.Launcher\Program.cs` -> `RootLauncherHost.ShouldWaitForChild`):**
   - `reEngine.Launcher` delegated directly to `Foundation.Launcher.RootLauncherHost.Run(...)`, whose `ShouldWaitForChild` returned `true` only when `--version`, `-v`, `--help`, `-h`, `/?`, `help`, or `--dry-run` appeared anywhere, OR when `args[0]` did not begin with `'-'`. Passing flags before a positional file, or passing `--open`, `--wait`, `--check-updates`, or `--register-assoc`, left `isCliOrSyncWait == false` so root `reEngine.exe` returned `0` immediately without propagating `app\reEngine.exe`'s exit code.

3. **`RecompLaunchCoordinator` -> `reStation` CLI Seam & Data Isolation (`RecompLaunchCoordinator.cs`):**
   ```csharp
   psi.ArgumentList.Add("--module");
   psi.ArgumentList.Add(loaded.PackagePath);
   if (!string.IsNullOrWhiteSpace(loaded.PreloadMedia.PrimaryMediaPath))
   {
       psi.ArgumentList.Add("--preload-media");
       psi.ArgumentList.Add(loaded.PreloadMedia.PrimaryMediaPath);
   }
   psi.ArgumentList.Add("--data-dir");
   psi.ArgumentList.Add(env.DataDirectory);
   ```
   - `reStation v0.1.0` [`CliOptions.Parse`](<PROJECTS_ROOT>/Personal/reStation/Dev/src/reStation.Core/Core/CliOptions.cs#L61-L126) accepted `--disc <image>` and rejected `--preload-media` (`exit 2`).
   - `RecompLaunchCoordinator` omitted `--log-dir` and `--config`, never parsed/forwarded `--wait`, and passed `reEngine`'s own `DataDirectory` directly to child engines (colliding on `settings.json`).

4. **Duplicate `[HEARTBEAT]` Prefix (`Program.cs`):**
   - `Foundation.Core.HeartbeatLogger` formatted `"[HEARTBEAT] {_operationName}: ..."`, and `Program.cs` passed `line => log("HEARTBEAT", line)` where `Log` emitted `$"[{level}] {msg}"`.

## 5. Constraints & Architectural Recommendations for `@pland`

1. **`reEngine v0.1.1` Lockstep Patch Scope (Zero Breaking Changes on `0.1.x`):**
   - **Graceful Network Failures + Populated `recentLogs` (`Program.cs` & `UpdateCoordinator.cs`):** Catch `HttpRequestException` / `IOException` / `TaskCanceledException` in `RunUpdateCheckCliAsync` (logging `[WARN]` and returning cleanly instead of throwing crash dumps on offline/dropped sockets); pass `SnapshotRecentLogs()` to `CrashBundleService.TryWriteCrashBundle` in `Program.Main`'s `catch` block; emit single `[HEARTBEAT]` lines (strip/omit redundant `"HEARTBEAT"` wrapper or log under `"INFO"` when forwarding `HeartbeatLogger` lines).
   - **Synchronous Root Wait (`reEngine.Launcher` + `--wait`):** While respecting the read-only `Foundation\` boundary (and logging an upstream proposal to `Foundation\Dev\docs\reports\` if `RootLauncherHost` should also recognize `--wait`/`--check-updates`/`--register-assoc`), ensure `reEngine.Launcher` blocks synchronously and propagates child `ExitCode` whenever `--wait`, `--open`, `--check-updates`, `--register-assoc`, `--dry-run`, `--help`, `--version`, or positional package args are supplied anywhere in `args`.
   - **`reStation` Launch Contract Alignment (`RecompLaunchCoordinator.cs`):** Coordinate with `reStation v0.1.1` so `reEngine` emits `--disc` (or both `--disc` / `--preload-media` once supported), forwards `--log-dir` when specified, isolates child module data under `<dataDir>\modules\<moduleId>\`, and sweeps all installed `(engineId, track)` pairs in `RunUpdateCheckCliAsync` rather than `FirstOrDefault()`.
