## 4. Non-Blocking Upstream & Minor Observations (For Future Triage)

1. **Upstream `Foundation.Installer` `--data-dir` vs. `--install-dir` Boundary (`InstallerEngine.Core.cs#L370`):**
   `ValidateAndNormalizeInstallDirectory` calls `EnsureWithinDirectory(_ctx.DataDirectory, resolved)` directly on `--data-dir` instead of resolving a shared `Sandbox\` ancestor boundary (as `reEngine.App.Program.ResolveSandboxBoundary` does). Passing sibling `--data-dir "...\Sandbox\data"` with `--install-dir "...\Sandbox\installed"` rejects `--install-dir`; omitting `--data-dir` lets `TryAdoptSafeTestDataDirectory` adopt `Sandbox\installed` cleanly. *(Recommend logging to `Foundation\Dev\docs\reports\` if sibling `--data-dir` + `--install-dir` CLI ergonomics are desired.)*
2. **Upstream `Foundation.Launcher` Sync-Wait Flag List (`RootLauncherHost.cs#L118-L141`):**
   `RootLauncherHost.ShouldWaitForChild` waits synchronously for `--version`, `-v`, `--help`, `-h`, `/?`, `help`, `--headless`, `--dry-run`, and positional non-flag targets, but does **not** wait for `--check-updates`, `--register-assoc`, `--visible-test`, or `--open` (when `--test-mode` precedes `--open` without `--dry-run`). Consequently, the root `reEngine.exe` stub returns `0` asynchronously without propagating `app\reEngine.exe`'s exit code if the child fails (observed during the initial `SocketException` run where `app\reEngine.exe` exited `1` while root `reEngine.exe` exited `0`).
3. **Crash Bundle `recentLogs` Empty (`Program.cs#L83`):**
   In `crash_reengine_20261113_132851_356.json`, `"recentLogs": []` despite `reengine.log` containing line 6 (`[HEARTBEAT]`), because `CrashBundleService.TryWriteCrashBundle(...)` in the `catch` block is called without passing the recent-logs snapshot provider.
